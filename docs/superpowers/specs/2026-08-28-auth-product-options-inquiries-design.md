# VITALEAF 인증·구매 옵션·1:1 문의 확장 설계

## 목표

현재 동작하지 않는 회원가입, 회원 로그인, 관리자 로그인을 실제 배포 환경에서 정상화한다. 상품 하나 안에 제조사가 밀봉한 `2개월분`, `4개월분` 같은 구매 옵션을 두고 옵션마다 가격 조정액과 재고를 관리한다. 같은 상품과 같은 옵션을 다시 장바구니에 담을 때 고객이 기존 수량 유지 또는 추가를 명확히 선택할 수 있게 한다. 회원과 주문 확인을 마친 비회원이 이용할 수 있는 1:1 문의 게시판과 관리자 답변 흐름을 추가한다.

기존 Next.js, Firebase, Vercel 구조를 유지한다. 별도 데이터베이스나 별도 고객센터 서비스를 도입하지 않아 직원의 학습·관리 부담을 늘리지 않으면서, 현재 막혀 있는 핵심 구매·상담 흐름을 실제로 사용할 수 있게 만드는 데 집중한다.

## 확인된 현상과 원인

최신 Preview 배포에서 로그인 화면은 렌더링되지만 Firebase 인증 요청은 일반 오류로 끝난다. 배포된 브라우저 번들에서 필요한 `NEXT_PUBLIC_FIREBASE_*` 값이 확인되지 않았다. 회원과 관리자가 같은 Firebase 클라이언트를 사용하므로, Preview 빌드에 공개 Firebase 설정이 빠지면 회원가입·회원 로그인·관리자 로그인이 함께 실패한다.

관리자 로그인은 클라이언트 설정 복구 외에도 다음 조건이 모두 필요하다.

- Firebase Authentication의 Email/Password 공급자 활성화
- 실제 Production 도메인과 고정 Preview 별칭의 승인 도메인 등록
- Firebase Authentication 관리자 계정 생성
- `admins/{uid}` 문서의 `role: "admin"` 설정

현재 오류 변환 로직은 알 수 없는 Firebase 오류를 모두 일반 메시지로 감춰 운영자가 설정 누락을 구분하기 어렵다. 인증 설정 오류를 안전한 한국어 안내로 세분화한다.

## 범위

### 포함

- Vercel Preview·Production의 Firebase 공개 설정과 재배포 검증
- 회원가입, 회원 로그인, 로그아웃, 관리자 로그인 정상화
- Firebase 인증 설정 오류의 구체적인 사용자·운영 안내
- 상품 내부의 구조화된 구매 옵션
- 옵션별 기간, SKU, 가격 조정액, 재고, 판매 여부, 기본 옵션
- 기존 옵션 없는 상품의 하위 호환
- 관리자 상품 등록·수정 화면의 옵션 관리
- 목업 상품의 2개월분·4개월분 옵션
- 옵션 단위 장바구니 항목과 중복 담기 선택 대화상자
- 주문 생성 시 옵션별 최신 가격·재고 서버 검증
- 회원·검증된 비회원의 1:1 문의 작성·조회
- 관리자 문의 목록, 필터, 미답변 배지, 답변, 삭제
- 문의 이미지 최대 3장, 파일당 최대 5MB
- Firestore·Storage 권한과 자동화 테스트
- Preview 전체 흐름 검증 후 Production 배포 준비

### 제외

- 제품을 개봉하거나 소분해 판매하는 기능
- 실제 PG 결제, 취소, 환불
- 이메일·문자·카카오 알림
- 실시간 상담 채팅
- 상담원 권한 등급과 담당자 자동 배정
- Supabase 또는 별도 데이터베이스로 이전
- 구매 옵션별로 상품 문서를 복제하는 방식

외부 알림과 상담원 배정은 현재 문의량이 확인되지 않은 단계에서는 운영 설정과 유지관리 비용에 비해 체감 이점이 작다. 첫 버전은 사이트 안의 미답변 배지와 상태 표시로 충분히 빠르게 처리할 수 있게 한다.

## 채택한 접근

### 상품 하나 안의 구조화된 구매 옵션

한 상품 문서에 공통 설명, 이미지, 성분, 인증 정보를 한 번만 저장하고 `purchaseOptions[]`에 판매 단위를 둔다. 예를 들어 4개월분을 기본 옵션으로 두고 2개월분은 별도의 밀봉 상품 옵션으로 관리한다.

이 방식은 옵션별 상품 문서를 복제하는 방식보다 관리자가 설명과 이미지를 여러 번 수정하지 않아도 되고, 검색 결과에 사실상 같은 제품이 반복 노출되지 않는다. 화면에서 가격만 임의 변경하는 방식과 달리 옵션별 재고와 주문 이력이 정확히 남는다.

## 데이터 모델

### 상품 구매 옵션

상품의 새 필드 예시는 다음과 같다.

```ts
type PurchaseOption = {
  id: string;
  label: string;
  durationMonths?: number;
  sku: string;
  priceAdjustment: number;
  stock: number;
  active: boolean;
  isDefault: boolean;
};

type Product = {
  // 기존 필드
  price: number;
  stock: number;
  purchaseOptions?: PurchaseOption[];
};
```

규칙은 다음과 같다.

- `id`는 상품 안에서 변하지 않는 내부 식별자다.
- `label`은 `2개월분`, `4개월분`처럼 고객에게 보이는 이름이다.
- `durationMonths`는 월 단위 기간 상품에 사용하며, 기간이 없는 옵션을 위해 선택 필드로 둔다.
- `sku`는 상품 안에서 중복되지 않아야 하며 관리 화면에서 자동 제안 후 수정할 수 있다.
- `priceAdjustment`는 원 단위 정수이며 음수와 양수를 모두 허용한다.
- 최종 판매가는 `product.price + option.priceAdjustment`다.
- 최종 판매가가 1원 미만이면 저장할 수 없다.
- `stock`은 해당 옵션만의 재고다.
- 판매 가능한 옵션 중 기본 옵션은 정확히 하나만 둔다.
- 옵션을 비활성화해도 과거 주문의 옵션 스냅샷은 유지한다.

옵션이 있는 상품의 실제 판매 가능 수량은 옵션별 `stock`이 기준이다. 기존 목록·품절 판정 코드와의 호환을 위해 상품 최상위 `stock`은 활성 옵션 재고 합계로 동기화하되, 주문 검증에서는 사용하지 않는다.

옵션이 없는 기존 상품은 런타임에서 `id: "default"`, 기본가격, 기존 재고를 쓰는 암시적 기본 옵션으로 정규화한다. 따라서 기존 Firestore 문서를 즉시 일괄 수정하지 않아도 목록·상세·장바구니가 깨지지 않는다.

### 장바구니 항목

장바구니의 동일 항목 기준은 `productId + purchaseOptionId`다.

```ts
type CartLine = {
  lineId: string;
  productId: string;
  purchaseOptionId: string;
  purchaseOptionLabel: string;
  sku: string;
  name: string;
  thumbnailUrl: string;
  unitPrice: number;
  stock: number;
  quantity: number;
  selected: boolean;
};
```

`unitPrice`, 옵션명, SKU는 고객에게 표시하기 위한 장바구니 스냅샷이다. 주문 확정 시에는 이 값을 신뢰하지 않고 서버가 최신 상품과 옵션을 다시 조회한다.

### 주문 항목

회원 주문과 비회원 주문의 각 `lines[]`에는 다음 옵션 스냅샷을 추가한다.

- `productId`
- `purchaseOptionId`
- `purchaseOptionLabel`
- `sku`
- `basePrice`
- `priceAdjustment`
- `unitPrice`
- `quantity`
- `lineTotal`

과거 주문은 상품 옵션이 나중에 수정되거나 비활성화되어도 주문 당시 내용을 그대로 보여준다.

### 1:1 문의

`inquiries/{inquiryId}` 문서는 다음 정보를 가진다.

- `ownerType`: `member` 또는 `guest`
- `memberUid`: 회원 문의일 때만 저장
- `guestOrderNumber`: 비회원 문의일 때만 저장
- `orderNumber`: 주문 관련 회원 문의의 선택 연결값
- `category`: `order`, `shipping`, `product`, `return`, `other`
- `title`, `body`
- `status`: `waiting` 또는 `answered`
- `attachments[]`: 저장 경로, 원본 파일명, MIME, 크기
- `adminReply`, `repliedAt`, `repliedBy`
- `createdAt`, `updatedAt`

비회원 휴대전화 원문은 문의 문서에 복제하지 않는다. 문의 접근 때마다 주문번호와 검증 정보가 기존 비회원 주문과 일치하는지 서버에서 확인한다.

## 사용자 경험

### 상품 상세의 구매 옵션

- 구매 옵션을 가격과 함께 표시한다. 예: `2개월분 · 45,000원`.
- 옵션을 선택하면 가격, 옵션 재고, 예상 복용 기간이 즉시 바뀐다.
- 기본 옵션을 처음부터 선택해 추가 단계를 줄인다.
- 품절·비활성 옵션은 선택할 수 없고 이유를 표시한다.
- 장바구니와 바로구매는 항상 선택 옵션을 포함한다.
- 모바일에서는 선택 영역과 하단 구매 바가 서로 가리지 않게 한다.
- 상품 목록·검색 카드에는 활성 옵션 중 가장 낮은 가격을 표시하고 가격이 여러 개면 `45,000원부터`처럼 표기한다.

### 같은 옵션 다시 담기

동일 상품의 동일 옵션이 이미 장바구니에 있을 때만 선택 대화상자를 연다.

```text
같은 상품과 구매 옵션이 장바구니에 있습니다.

현재 장바구니: 2개
이번 선택 수량: 1개

[기존 수량 유지]  [1개 추가하여 3개로 변경]
```

- `기존 수량 유지`는 장바구니를 바꾸지 않는다.
- `추가`는 기존 수량에 이번 수량을 더한다.
- 추가 결과가 재고를 넘으면 가능한 최대 수량과 이유를 알린다.
- 같은 상품의 다른 옵션은 별도 장바구니 줄로 바로 추가한다.
- 데스크톱은 중앙 대화상자, 모바일은 읽기 쉬운 하단 시트를 사용한다.
- 닫기와 Escape는 안전하게 기존 수량 유지로 처리한다.
- 수량과 결제예정금액, 헤더 장바구니 배지를 같은 상태 변경에서 즉시 갱신한다.

### 관리자 옵션 관리

상품 등록·수정의 판매 단계에 `구매 옵션 관리`를 둔다.

- 옵션 추가, 복제, 삭제, 순서 변경
- 옵션명, 기간, SKU, 가격 조정액, 재고, 판매 여부 입력
- 기본 옵션 지정
- 기본가격, 조정액, 최종가격 동시 표시
- 음수 조정액을 명시적으로 허용
- 최종가격 1원 미만, 음수 재고, 중복 SKU, 기본 옵션 누락을 저장 전에 차단
- 옵션 복제로 비슷한 기간 상품을 빠르게 등록

목업 상품은 2개월분과 4개월분을 제공한다. 2개월분 가격 조정액은 상품마다 다르게 두어 정확히 절반인 사례와 절반보다 비싼 사례를 모두 테스트한다.

### 회원 문의

- 마이페이지에 `1:1 문의` 메뉴를 추가한다.
- 목록에서 문의 유형, 제목, 작성일, 답변 상태를 확인한다.
- 작성 화면에서 문의 유형, 관련 주문, 제목, 내용, 이미지를 입력한다.
- 상세 화면에서 원문, 첨부 이미지, 관리자 답변을 확인한다.
- 고객은 문의를 삭제하거나 관리자 답변을 수정할 수 없다.

### 비회원 문의

- 비회원 주문조회에서 주문번호와 주문 당시 휴대전화를 확인한다.
- 확인 성공 후 해당 주문에 대한 문의 작성·목록·상세 진입을 제공한다.
- 서버는 현재 화면에서만 사용하는 짧은 유효기간의 문의 검증 토큰을 발급한다.
- 검증 토큰은 URL이나 영구 로컬 저장소에 넣지 않는다.
- 같은 화면에서 파일 업로드와 문의 저장 때 전화번호를 반복 입력하지 않는다.
- 나중에 다시 방문하면 주문번호와 휴대전화로 다시 확인한다.

### 관리자 문의 처리

- 관리자 화면에 `1:1 문의` 메뉴와 미답변 개수 배지를 표시한다.
- 답변 상태와 문의 유형으로 필터링한다.
- 문의 상세에서 주문 연결 정보, 문의 내용, 첨부 이미지를 보고 답변한다.
- 답변 저장 시 상태가 `answered`로 바뀌고 답변자와 시간이 기록된다.
- 관리자만 문의와 연결된 이미지를 삭제할 수 있다.
- 첫 버전에는 외부 알림을 두지 않고 마이페이지 상태와 관리자 배지를 사용한다.

## 인증 정상화

### 배포 설정

다음 공개 설정이 Vercel Preview와 Production 빌드에 모두 존재하는지 값 자체를 노출하지 않고 확인한다. Analytics를 사용하지 않는 환경에서는 Measurement ID만 선택값으로 둔다.

- `NEXT_PUBLIC_FIREBASE_API_KEY`
- `NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN`
- `NEXT_PUBLIC_FIREBASE_PROJECT_ID`
- `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET`
- `NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID`
- `NEXT_PUBLIC_FIREBASE_APP_ID`
- `NEXT_PUBLIC_FIREBASE_MEASUREMENT_ID`

`NEXT_PUBLIC_*` 값은 빌드 때 브라우저 번들에 들어가므로 설정 변경 후 반드시 새 배포가 필요하다. Firebase Auth 승인 도메인에는 매번 바뀌는 개별 Preview URL 대신 Vercel의 고정 Preview 별칭과 Production 도메인을 등록한다.

### 회원 인증

- Email/Password 공급자 활성화를 배포 체크리스트에 포함한다.
- 회원가입 성공 후 회원 프로필을 멱등적으로 생성·보완한다.
- 중복 이메일, 약한 비밀번호, 잘못된 로그인 정보, 네트워크 오류를 한국어로 안내한다.
- 인증 설정 누락과 승인되지 않은 도메인은 일반 비밀번호 오류와 구분한다.
- 로그인 후 안전하게 검증한 `next` 경로로 복귀한다.

### 관리자 인증

- Firebase Authentication에서 로그인한 UID의 `admins/{uid}.role`이 `admin`인지 확인한다.
- 일반 회원은 관리자 계정으로 승격되지 않으며 관리자 경로 진입을 차단한다.
- 관리자 문서 누락은 `관리자 권한이 등록되지 않았습니다`로 안내한다.
- 서버 API도 클라이언트 화면과 별도로 ID 토큰과 관리자 역할을 다시 검증한다.

## 문의 API와 저장소 보안

### API 경계

문의 데이터는 브라우저가 Firestore에 직접 쓰지 않는다. Firebase Admin SDK를 사용하는 서버 API가 회원 토큰, 비회원 주문 검증 또는 관리자 권한을 확인한 뒤 처리한다.

개념적인 경로는 다음과 같다.

- `POST /api/inquiries/guest-verify`: 주문번호·휴대전화 확인과 짧은 검증 토큰 발급
- `POST /api/inquiries`: 문의 생성
- `POST /api/inquiries/list`: 회원 또는 검증된 주문의 문의 목록
- `POST /api/inquiries/detail`: 문의 상세
- `POST /api/inquiries/upload-url`: 일회성 이미지 업로드 주소 발급
- `POST /api/admin/inquiries/reply`: 관리자 답변
- `POST /api/admin/inquiries/delete`: 관리자 삭제

민감한 주문 검증값은 URL 쿼리로 보내지 않는다. 오류는 주문 존재 여부와 전화번호 불일치 여부를 따로 노출하지 않는다. 반복 검증 실패에는 기존 비회원 주문조회 제한을 재사용한다.

### 이미지 업로드

Vercel Function 요청 본문은 최대 4.5MB이므로 파일당 5MB 조건을 서버 프록시 업로드로 구현하지 않는다. 서버가 권한 확인 후 Firebase Storage의 짧은 유효기간 서명 업로드 주소를 발급하고 브라우저가 Storage로 직접 전송한다.

- 허용 형식: JPG, PNG, WebP
- 파일당 최대 5MB
- 문의당 최대 3장
- 업로드 주소는 짧게 만료되고 임의 경로를 선택할 수 없다.
- 문의 저장 전에 서버가 실제 객체의 MIME, 크기, 경로와 파일 시그니처를 다시 확인한다.
- 파일 확장자만 이미지로 바꾼 경우를 차단한다.
- 조회 시에도 회원·주문·관리자 권한을 확인한 뒤 짧은 읽기 주소를 반환한다.
- 최초 파일은 `pending/{uploadSessionId}` 아래에 저장하고 문의 생성이 성공하면 `inquiries/{inquiryId}` 경로로 확정한다.
- 작성 취소로 남은 `pending` 파일은 Storage 수명주기 정책으로 자동 정리한다.
- 문의 삭제 시 관리자 API가 연결된 Storage 객체도 함께 제거한다.

Firestore 클라이언트 규칙은 문의 컬렉션의 직접 읽기·쓰기를 거부하고 서버만 접근하게 한다. Storage도 일반 공개 목록·읽기·쓰기를 허용하지 않는다.

## 주문과 재고의 서버 검증

장바구니는 빠른 화면 반응을 위해 로컬 상태를 유지하지만 주문 확정은 서버가 담당한다.

1. 상품 ID와 옵션 ID가 존재하는지 확인한다.
2. 옵션이 활성 상태인지 확인한다.
3. 옵션별 현재 재고가 주문 수량 이상인지 확인한다.
4. 기본가격과 가격 조정액으로 최종 단가를 다시 계산한다.
5. 배송비와 총액을 서버에서 다시 계산한다.
6. 검증한 옵션 스냅샷으로 주문을 저장한다.

가격 또는 재고가 바뀌었으면 조용히 주문하지 않고 변경 내용을 고객에게 보여주고 재확인을 요청한다. 옵션 없는 레거시 상품은 암시적 기본 옵션으로 같은 검증 경로를 사용한다.

## 오류 처리

- 옵션 목록이 잘못된 레거시 상품은 안전한 기본 옵션으로 표시하되 관리자 화면에 수정 필요 상태를 알린다.
- 장바구니의 오래된 옵션이 삭제·비활성화되었으면 결제 전에 해당 줄을 명확히 표시한다.
- 재고 초과는 가능한 최대 수량을 알리고 결제예정금액을 즉시 다시 계산한다.
- 문의 파일 일부가 실패하면 성공한 파일까지 숨기지 않고 재시도 대상을 구분한다.
- 문의 생성 실패 시 입력 내용은 유지하고 재시도할 수 있게 한다.
- 인증 설정 오류 메시지에 API 키나 서버 자격 증명을 포함하지 않는다.
- 서버 로그에는 전체 휴대전화, 주소, 토큰, Firebase 비밀값을 기록하지 않는다.

## 테스트와 검증

### 자동 테스트

- 옵션 최종가격 계산과 음수·양수 조정액
- 최종가격 1원 미만, 음수 재고, 중복 SKU, 기본 옵션 오류 차단
- 옵션 없는 상품의 기본 옵션 정규화
- 같은 상품·같은 옵션의 유지와 추가 선택
- 같은 상품·다른 옵션의 별도 장바구니 줄
- 재고 상한과 수량·결제예정금액 즉시 갱신
- 주문 서버의 옵션 가격·재고 재검증
- 회원가입·로그인 오류 코드 변환
- 일반회원의 관리자 접근 차단
- 회원 문의의 사용자별 격리
- 비회원 주문번호·휴대전화 검증과 반복 실패 제한
- 문의 파일 형식·크기·개수 검증
- 관리자만 답변·삭제할 수 있는지 확인
- Firestore·Storage의 브라우저 직접 접근 거부

### 브라우저 검증

- 회원가입 → 마이페이지 → 로그아웃 → 재로그인
- 관리자 로그인 → 상품 옵션 등록·수정 → 상세 반영
- 상품 상세 옵션 선택 → 장바구니 중복 대화상자 → 수량·총액 확인
- 다른 옵션을 담아 별도 줄 생성
- 비회원 주문조회 → 문의 작성 → 이미지 첨부 → 문의 조회
- 회원 문의 작성 → 관리자 답변 → 회원 답변 확인
- 관리자 미답변 배지·필터·삭제
- 모바일 하단 시트, 옵션 선택, 첨부 이미지, 문의 상세

검증은 lint, 타입 검사, 전체 테스트, Next.js Production 빌드, 실제 Preview 브라우저 흐름을 포함한다.

## 배포 순서

1. 로컬 자동 테스트와 Production 빌드를 통과한다.
2. Vercel Preview와 Production 환경의 공개 Firebase 설정 존재 여부를 확인한다.
3. Firebase Email/Password 공급자와 승인 도메인을 확인한다.
4. 관리자 Auth 계정과 `admins/{uid}` 역할 문서를 확인한다.
5. Firestore 규칙·복합 인덱스, Storage 설정, 필요한 서버 비밀값을 준비한다.
6. Preview를 새로 배포하고 회원·관리자·옵션·문의 전체 흐름을 검증한다.
7. 검증 결과와 필요한 운영 설정을 사용자에게 보고한다.
8. Production 배포는 검증 후 승인된 범위에서 진행한다.

비밀값은 저장소, 문서, 채팅, 브라우저 로그에 출력하지 않는다. 공개 Firebase 설정과 서버 전용 Firebase Admin 자격 증명은 이름과 사용 범위를 분리한다.

## 완료 기준

- Preview와 Production에서 회원가입과 회원 로그인이 정상 동작한다.
- 관리자 권한 계정만 관리자 화면에 로그인할 수 있다.
- 관리자가 상품 한 개에서 여러 밀봉 구매 옵션과 옵션별 가격·재고를 쉽게 관리한다.
- 고객이 옵션별 최종가격과 재고를 이해하고 구매할 수 있다.
- 동일 상품·동일 옵션 재담기에서 기존 수량 유지 또는 추가를 직접 선택한다.
- 장바구니와 주문의 옵션·가격·재고가 일관되고 서버에서 재검증된다.
- 회원과 검증된 비회원만 자신의 문의를 작성·조회한다.
- 관리자에게 미답변 문의가 보이고 답변·삭제가 권한대로 동작한다.
- 5MB 이미지 3장이 Vercel 요청 제한에 걸리지 않고 안전하게 업로드된다.
- 데스크톱과 모바일의 핵심 흐름이 자동 테스트와 실제 Preview에서 모두 검증된다.
