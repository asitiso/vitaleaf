# 바이탈리프 건강기능식품 쇼핑몰 설계

## 1. 목표

30~50대 고객이 건강기능식품의 기능성, 원료, 함량, 섭취 방법을 쉽게 비교하고 장바구니부터 주문 완료까지 혼동 없이 진행할 수 있는 전문 쇼핑몰을 만든다. 운영자는 50개 이상의 상품을 코드 수정 없이 Firestore에서 관리한다. 화면과 기능은 React/Next.js 컴포넌트와 경로로 분리해 기능 추가와 유지보수를 쉽게 한다.

이번 단계의 성공 기준은 다음과 같다.

- 첫 화면에서 상품 검색, 전체 카테고리, 베스트상품, 첫 구매 혜택을 즉시 찾을 수 있다.
- 상품 상세에서 핵심 기능성, 1일 섭취량, 원료·함량, 원산지, 인증, 주의사항을 빠르게 확인할 수 있다.
- 모바일에서 상세 상품을 보다가 고정 구매 바를 통해 장바구니 또는 주문으로 바로 이동할 수 있다.
- 장바구니 수량과 선택 상태가 새로고침 뒤에도 유지된다.
- 운영자는 로그인 후 상품을 한 건씩 추가·수정·삭제하거나 CSV로 여러 상품을 일괄 등록할 수 있다.
- 결제는 목업으로 종료하되, 나중에 PG SDK로 교체할 함수 경계가 명확하다.

## 2. 검토한 접근법

### 대안 1: 단일 HTML SPA + Firebase CDN

`index.html` 하나에 화면 마크업, 스타일, 라우팅, 상태 관리, Firebase 연동을 포함한다. 해시 라우팅으로 메인, 상품목록, 상세, 장바구니, 주문, 관리자 화면을 전환한다.

- 장점: 별도 빌드 과정 없이 파일 하나로 실행·배포할 수 있고 요청한 기술 조건에 정확히 맞는다.
- 단점: 코드가 길어지고 화면별 모듈 분리가 제한된다.
- 미선택 이유: 기능 수가 늘어나면서 하나의 파일을 수정할 때 다른 화면에 영향을 줄 위험과 유지보수 부담이 커진다.

### 선택안: React/Next.js 다중 페이지 + Firebase

Next.js App Router 구조에서 화면별 경로와 공통 UI, Firebase 데이터 계층, 장바구니 상태를 분리한다.

- 장점: 메인, 상품, 장바구니, 주문, 관리자 기능의 책임이 분명해진다. 기능을 추가하거나 오류를 수정할 때 관련 파일만 다룰 수 있어 장기 유지보수가 쉽다.
- 단점: 패키지 설치, 빌드, 배포 과정이 추가된다.
- 선택 이유: 사용자가 대안 1을 선택했다. 이번 프로젝트는 화면과 기능이 많아 초기 설정 비용보다 이후 수정 시간 절감 효과가 크다.

### 대안 2: 정적 상품 데이터만 사용하는 HTML

구현은 가장 빠르지만 50개 이상 상품을 수정할 때 매번 코드를 편집해야 한다. 관리자 업무 시간이 크게 늘어나므로 채택하지 않는다.

## 3. 시각 디자인

승인된 방향은 `세이지 & 샌드` 테마다.

- 기본 그린: `#215C45`
- 진한 그린: `#173F32`
- 샌드 배경: `#F7F3EB`
- 옅은 세이지: `#E6EFE7`
- 본문 배경: `#FFFEFB`
- 본문 글자: `#183229`
- 할인 강조: `#C94E3C`

Pretendard와 Noto Sans KR 계열을 사용한다. 30~50대 고객의 가독성을 위해 본문 크기와 명도 대비를 충분히 확보하고, 작은 회색 글자나 장식용 영문 남용을 피한다.

홈 화면에는 건강 고민 아이콘을 반복 노출하지 않는다. 해당 항목은 `전체 카테고리` 메가 메뉴 안에 상품 카테고리, 연령·대상별 메뉴와 함께 배치한다. 홈 화면은 프로모션, 베스트상품, 신뢰 근거에 집중한다.

## 4. 정보 구조와 화면

### 애플리케이션 구조

- `/`: 메인
- `/products`: 검색·필터·정렬이 있는 상품목록
- `/products/[id]`: 상품상세
- `/cart`: 장바구니
- `/checkout`: 주문·결제 목업
- `/order-complete`: 주문 완료
- `/admin`: 관리자 로그인과 상품관리

공통 레이아웃과 검색 헤더는 서버에서 안정적으로 렌더링하고, Firebase 조회·필터·장바구니·폼처럼 상호작용이 필요한 영역만 Client Component로 둔다. Firebase 초기화와 쿼리는 `lib/firebase`와 `lib/products`를 통해서만 사용해 화면 컴포넌트가 데이터 접근 세부사항에 의존하지 않게 한다.

### 공통 헤더

- 첫 구매 쿠폰, 무료배송 기준, 출고 시각을 보여주는 혜택 바
- 브랜드 워드마크
- 성분·효능·상품명 통합 검색
- 로그인, 마이페이지 안내, 장바구니 수량
- 전체 카테고리, 베스트, 오늘의 특가, 건강 고민별, 성분별, 선물세트, 브랜드 스토리 메뉴
- 전체 카테고리를 누르면 상품군, 건강 고민, 연령·대상, 첫 구매 추천을 담은 메가 메뉴 표시

### 메인 화면

- 대표 상품·프로모션 히어로와 보조 프로모션 두 개
- 식약처 인정 기능성 원료, GMP, 원산지·함량 공개, 품질검사 안내 바
- 실제 판매 순위 기반 베스트상품과 30대·40대·50대 탭
- 신상품 영역
- 원료·함량 공개 원칙을 설명하는 브랜드 신뢰 영역
- 모바일에서는 프로모션을 세로로 쌓고 상품을 2열로 표시

### 상품 목록

- 카테고리, 건강 고민, 가격 범위, 재고 여부 필터
- 인기순, 최신순, 낮은 가격순, 높은 가격순 정렬
- 적용 필터를 한 번에 확인하고 개별 해제할 수 있는 필터 칩
- 상품 카드에 기능성 태그, 할인율, 현재가, 정상가, 별점, 리뷰 수, 혜택 배지 표시
- 결과 없음, 로딩 중, 통신 오류 상태를 각각 구분

### 상품 상세

- 썸네일을 포함한 이미지 갤러리와 이미지 오류 대체 화면
- 상품명, 가격, 재고, 배송 혜택, 수량 선택
- 핵심 기능성 3개까지 요약
- 섭취 방법, 성분·함량, 원산지, 인증, 주의사항 아코디언
- 성분표는 성분명, 1일 섭취량당 함량, 영양성분 기준치 비율로 표시
- 승인된 리뷰의 별점 평균, 분포, 최신 리뷰 표시
- 모바일 하단 고정 장바구니·바로구매 바

### 장바구니

- 상품 선택, 전체 선택, 수량 증감, 개별 삭제
- 재고를 초과하는 수량 선택 방지
- 선택 상품 금액, 배송비, 결제 예정 금액 자동 계산
- 무료배송까지 남은 금액 안내
- `localStorage`에 저장하고 다른 탭의 변경도 반영

### 주문·결제

- 주문자, 연락처, 우편번호, 주소, 상세주소, 배송 요청사항
- 필수 입력과 전화번호 형식 검증
- 카드, 계좌이체, 간편결제 선택 UI
- 상품·배송비·총액 주문 요약
- `processPayment(orderDraft)` 함수가 목업 주문번호를 만들고 완료 화면으로 이동
- 실제 PG 연동 시 이 함수만 교체할 수 있도록 결제 UI와 분리
- 목업 단계에서는 개인정보와 주문을 Firestore에 저장하지 않는다.

### 관리자

- Firebase Authentication 이메일·비밀번호 로그인
- `admins/{uid}` 문서가 존재하는 사용자만 상품 쓰기 허용
- 상품 목록 검색, 신규 등록, 수정, 삭제, 품절 전환
- 이미지 파일 업로드 대신 이미지 URL 입력을 사용해 Firebase Storage 관리 부담을 제외
- CSV 템플릿 다운로드, CSV 검증, Firestore 일괄 등록
- 현재 상품 CSV 내보내기
- 삭제 전 확인과 저장 성공·실패 메시지

CSV 일괄 등록은 50개 이상의 상품을 폼으로 반복 입력하는 시간을 크게 줄이므로 포함한다. 반면 이미지 직접 업로드는 Storage 권한·용량·정리 정책까지 추가되어 이번 단계의 편의 향상보다 관리 부담이 크므로 제외한다.


이번 단계에서는 리뷰 조회만 구현한다. 리뷰 작성과 신고·승인 기능은 인증·운영 정책이 필요하고 구매 흐름 개선 효과가 제한적이므로 후속 범위로 둔다.

### `admins/{uid}`

```text
role: "admin"
displayName: string
```

## 6. 데이터 흐름과 상태

1. 시작 시 Firebase를 초기화하고 Firestore의 `products`를 읽는다.
2. 50~300개 상품은 브라우저 메모리에 캐시해 검색과 복합 필터를 즉시 처리한다.
3. Firestore가 비어 있으면 가짜 상품을 섞지 않고 관리자 등록 안내가 포함된 빈 상태를 표시한다.
4. 장바구니와 최근 본 상품 ID는 `localStorage`에 저장한다.
5. 상품 수정 후 관리자 화면과 고객 화면 캐시를 즉시 갱신한다.
6. 리뷰는 상세 화면 진입 시 해당 상품의 승인된 리뷰만 별도로 조회한다.

Firestore 전문 검색 서비스는 이번 상품 수에서 비용과 운영 복잡성 대비 이득이 작다. 상품 수가 수천 개로 늘어나면 Algolia 등 검색 서비스 도입을 재검토한다.

## 7. Firebase 보안

- 상품 읽기와 승인된 리뷰 읽기는 공개한다.
- 상품 쓰기는 로그인 상태이면서 `admins/{uid}` 문서가 존재할 때만 허용한다.
- 리뷰 쓰기와 주문 쓰기는 이번 단계에서 차단한다.
- 제공된 Firebase 웹 설정값은 공개 클라이언트 식별자이며, 실제 보호는 Firestore Rules와 관리자 인증으로 처리한다.
- 관리자 계정 생성과 `admins/{uid}` 등록 절차를 운영 안내에 기록한다.

## 8. 오류 처리와 접근성

- Firestore 로딩 중에는 레이아웃이 흔들리지 않는 스켈레톤을 표시한다.
- 권한 거부, 네트워크 오류, 빈 데이터 상태에 서로 다른 안내와 재시도 버튼을 제공한다.
- 이미지 오류는 상품명을 포함한 대체 카드로 바꾼다.
- 폼 오류는 해당 필드 가까이에 표시하고 첫 오류로 포커스를 이동한다.
- 키보드로 메뉴, 탭, 아코디언, 모달, 수량 조절을 사용할 수 있게 한다.
- 색만으로 할인·선택·오류를 구분하지 않고 텍스트를 함께 제공한다.
- 모션 감소 환경에서는 불필요한 전환 효과를 끈다.

## 9. 검증 계획

- TypeScript 검사, 린트, Next.js 배포 빌드
- Firebase 초기화 성공·실패 상태 확인
- 상품 없음, 다수 상품, 품절 상품, 이미지 오류 상태 확인
- 검색, 카테고리, 가격, 정렬 조합 확인
- 상세 아코디언, 이미지 갤러리, 수량·재고 제한 확인
- 장바구니 새로고침 유지, 합계, 배송비, 전체 선택 확인
- 주문 폼 유효성 검사와 목업 주문 완료 확인
- 관리자 로그인 실패, 권한 없음, 상품 CRUD, CSV 오류·성공 확인
- 데스크톱과 모바일 너비에서 핵심 구매 흐름 확인
- 한글 UTF-8 표시 검사

## 10. 산출물

- `app/`: 메인, 상품목록, 상품상세, 장바구니, 주문, 관리자 경로
- `components/`: 공통 헤더, 상품 카드, 폼, 모달, 장바구니 UI
- `lib/`: Firebase, 상품 조회, 관리자 CRUD, CSV, 결제 목업 경계
- `contexts/`: 장바구니와 공통 사용자 상태
- `firestore.rules`: Firebase Console에 적용할 보안 규칙
- `products-template.csv`: 운영자가 상품을 일괄 등록할 때 사용하는 템플릿
- `README.md`: Firebase 관리자 설정, 실행, 배포, PG 교체 지점 안내

쇼핑몰은 Next.js 애플리케이션으로 동작하며, 보안 규칙과 CSV 템플릿은 운영을 위한 보조 자료다.
