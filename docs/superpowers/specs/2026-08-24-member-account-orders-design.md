# VITALEAF 회원 계정과 주문내역 설계

## 목표

비회원 구매 흐름은 유지하면서 이메일 회원에게 로그인, 저장 배송지, 주문내역 조회를 제공한다. 실제 PG 결제가 없는 현재 단계에 맞춰 회원 주문만 Firestore에 안전하게 저장하고, 비회원 주문은 개인정보를 서버에 남기지 않는 목업 흐름으로 유지한다.

## 범위

### 포함

- 이메일/비밀번호 회원가입
- 로그인, 로그아웃, 비밀번호 재설정
- 로그인 상태를 전역에서 제공하는 `AuthProvider`
- 헤더와 모바일 메뉴의 로그인 상태별 계정 메뉴
- 마이페이지의 회원정보, 기본 배송지, 주문내역
- 로그인 회원 결제 시 기본 배송지 자동입력
- 로그인 회원의 목업 주문 저장과 조회
- Firestore 사용자·주문 보안 규칙
- 인증, 체크아웃, 마이페이지, 보안 규칙 자동 테스트

### 제외

- Google, 카카오, 네이버 소셜 로그인
- 실제 PG 승인과 결제 검증
- 비회원 주문의 서버 저장 및 조회
- 이메일 인증을 구매 필수 조건으로 강제
- 쿠폰, 적립금, 찜 목록, 정기배송
- 관리자 주문 처리 화면

이 제외 범위는 현재 목업 결제 단계에서 유지관리 부담을 늘리면서 사용자 편의 차이는 작거나, 안전한 서버 결제 검증이 선행되어야 하는 기능이다.

## 사용자 경험

### 회원가입

`/signup`에서 이름, 이메일, 비밀번호, 비밀번호 확인, 이용약관 동의를 받는다. 비밀번호는 8자 이상이어야 하며 영문과 숫자를 각각 하나 이상 포함해야 한다. 계정 생성 후 `users/{uid}` 회원 문서를 만들고 즉시 로그인 상태로 `/mypage`에 이동한다. 이메일 인증 메일을 발송하고 마이페이지에 인증 안내를 표시하지만 현재 목업 구매는 차단하지 않는다.

회원 문서 생성이 실패하면 생성된 인증 계정을 삭제해 반쪽 계정이 남지 않도록 시도한다. 삭제까지 실패한 경우 재로그인 후 회원정보 생성 복구를 안내한다.

### 로그인과 비밀번호 재설정

`/login`은 이메일과 비밀번호를 받는다. 로그인 성공 후 `next` 쿼리가 동일 출처의 안전한 내부 경로이면 해당 경로로, 아니면 `/mypage`로 이동한다. 로그인 화면에서 이메일을 입력해 Firebase 비밀번호 재설정 메일을 보낼 수 있다.

Firebase 오류 코드는 다음 원칙으로 한국어 안내한다.

- 잘못된 이메일 또는 자격 증명: 이메일 또는 비밀번호 확인
- 이미 사용 중인 이메일: 기존 계정 로그인 안내
- 약한 비밀번호: 비밀번호 조건 안내
- 요청 과다: 잠시 후 재시도 안내
- 네트워크 오류: 연결 확인 안내
- 그 밖의 오류: 일반 재시도 안내

### 헤더

인증 상태 확인 중에는 계정 메뉴 자리를 고정해 레이아웃 이동을 줄인다. 로그아웃 상태에서는 `로그인`, 로그인 상태에서는 `마이페이지`와 `로그아웃`을 표시한다. 데스크톱과 모바일 메뉴에 같은 기능을 제공한다. 기존 관리자 링크는 유지한다.

### 마이페이지

`/mypage`는 클라이언트 인증 상태를 확인한다. 로그아웃 상태면 로그인 필요 안내와 `/login?next=/mypage` 링크를 제공한다. 로그인 상태에서는 다음을 제공한다.

1. 회원정보: 이메일은 읽기 전용, 이름과 연락처는 수정 가능
2. 기본 배송지: 받는 분, 연락처, 우편번호, 주소, 상세주소 수정 가능
3. 주문내역: 최신 주문부터 주문번호, 주문일, 상품 요약, 금액, 목업 주문상태 표시

주문내역이 없으면 상품 목록으로 이동하는 명확한 빈 상태를 표시한다.

### 체크아웃

비회원은 기존 체크아웃을 그대로 이용하고 서버에 개인정보나 주문을 저장하지 않는다. 로그인 회원은 회원 문서의 기본 배송지를 처음 한 번 자동입력한다. 사용자가 입력을 시작한 뒤 늦게 도착한 회원정보가 입력값을 덮어쓰지 않는다.

로그인 회원에게만 `이 배송지를 기본 배송지로 저장` 선택지를 표시한다. 제출 흐름은 다음 순서를 지킨다.

1. 입력값과 재고를 검증한다.
2. 기존 `processPayment` 목업 결제를 실행한다.
3. 로그인 회원이면 주문을 자신의 하위 컬렉션에 저장한다.
4. 선택한 경우 기본 배송지를 갱신한다.
5. 모든 필수 저장이 성공한 뒤 선택 상품을 장바구니에서 삭제한다.
6. 주문 완료 화면으로 이동한다.

회원 주문 저장이 실패하면 장바구니를 비우지 않고 오류를 표시한다. 비회원은 목업 결제 성공 직후 기존처럼 주문 완료 화면으로 이동한다.

## 데이터 모델

### `users/{uid}`

```ts
type UserProfile = {
  uid: string;
  email: string;
  displayName: string;
  phone: string;
  defaultAddress: {
    recipient: string;
    phone: string;
    postcode: string;
    address: string;
    addressDetail: string;
  } | null;
  termsAcceptedAt: Timestamp;
  createdAt: Timestamp;
  updatedAt: Timestamp;
};
```

`uid`와 `email`, `termsAcceptedAt`, `createdAt`은 생성 후 클라이언트에서 변경할 수 없다. 이름, 연락처, 기본 배송지만 본인이 수정할 수 있다.

### `users/{uid}/orders/{orderId}`

```ts
type MemberOrder = {
  id: string;
  userId: string;
  orderNumber: string;
  status: "mock-received";
  paymentMethod: "card" | "bank" | "easy";
  customerName: string;
  phone: string;
  shippingAddress: {
    postcode: string;
    address: string;
    addressDetail: string;
  };
  deliveryNote: string;
  lines: Array<{
    productId: string;
    name: string;
    quantity: number;
    unitPrice: number;
  }>;
  subtotal: number;
  shippingFee: number;
  total: number;
  createdAt: Timestamp;
};
```

주문 문서는 생성 후 클라이언트에서 수정하거나 삭제할 수 없다. 주문번호는 기존 `processPayment` 결과를 사용하고, 문서 ID는 주문번호와 별도의 충돌 없는 Firestore ID를 사용한다.

## 모듈 경계

- `features/auth/auth-context.tsx`: Firebase 사용자 상태 관찰과 UI용 세션 제공
- `lib/firebase/member-auth.ts`: 가입, 로그인, 로그아웃, 재설정 메일, 오류 변환
- `lib/firebase/user-profile.ts`: 회원 문서 생성·조회·수정
- `lib/firebase/member-orders.ts`: 회원 주문 생성·목록 조회와 도메인 변환
- `components/auth/*`: 로그인·회원가입 폼
- `components/account/*`: 마이페이지 프로필, 배송지, 주문내역
- `components/checkout/checkout-form.tsx`: 인증 상태에 따른 자동입력과 주문 저장 조율
- `components/shell/site-header.tsx`: 로그인 상태별 계정 메뉴

각 Firebase 모듈은 UI에서 직접 SDK 세부 구현을 다루지 않게 한다. 테스트에서는 어댑터 또는 함수 경계에서 Firebase 의존성을 교체한다.

## 인증 상태와 경쟁 조건

`AuthProvider`는 `checking`, `signed-out`, `signed-in` 상태를 제공한다. 구독 해제 후 도착한 콜백은 무시한다. 마이페이지와 체크아웃의 회원정보 요청은 현재 사용자 UID와 요청 시작 시점의 UID가 일치할 때만 화면에 반영한다. 로그아웃 직후 이전 사용자 데이터가 잠깐 보이지 않도록 상태를 즉시 초기화한다.

기존 관리자 인증은 같은 Firebase Auth 인스턴스를 사용한다. 일반 회원이 관리자 화면에서 로그인하면 기존 로직대로 관리자 문서 확인 후 로그아웃된다. 일반 쇼핑몰 로그인은 관리자 권한을 요구하지 않는다.

## 보안 규칙

`users/{uid}`는 인증 사용자의 UID가 경로 UID와 같을 때만 읽기와 생성을 허용한다. 업데이트 시 `uid`, `email`, `termsAcceptedAt`, `createdAt` 불변성을 검사한다. 삭제는 클라이언트에서 허용하지 않는다.

`users/{uid}/orders/{orderId}`는 경로 UID가 인증 UID와 같을 때만 읽기와 생성을 허용한다. 생성 시 `userId`가 인증 UID와 같고, `status`가 `mock-received`이며, 상품 배열이 비어 있지 않고, 수량·금액이 음수가 아니어야 한다. 업데이트와 삭제는 거부한다.

기존 `products`, `productDrafts`, `reviews`, `admins` 규칙은 유지한다. 기존 최상위 `orders`는 계속 모든 접근을 거부한다.

## 오류와 복구

- 인증 초기화 실패: 재시도 가능한 오류 안내
- 가입 중 회원 문서 실패: 인증 계정 삭제 보상 처리 후 재시도 안내
- 프로필 조회 실패: 로그인 상태는 유지하고 해당 영역만 재시도
- 배송지 저장 실패: 주문 저장 전에 발생하면 제출 중단, 주문 저장 뒤 발생하면 주문 완료는 유지하고 배송지 저장 실패 안내를 완료 화면 상태에 포함
- 주문 저장 실패: 장바구니 유지, 결제 화면에서 재시도
- 중복 제출: ref와 disabled 상태로 차단
- 로그아웃 실패: 현재 화면을 유지하고 오류 안내

목업 결제이므로 주문 저장 재시도에 실제 이중 결제 위험은 없지만, 같은 제출 내 중복 호출은 막는다. 실제 PG 연동 시 서버에서 주문 생성과 결제 승인에 멱등키를 도입해야 한다.

## 테스트 전략

### 단위·컴포넌트 테스트

- 회원가입 입력 검증과 Firebase 오류 메시지
- 안전한 `next` 경로 판별
- 인증 상태 전환과 로그아웃 시 사용자 데이터 초기화
- 헤더의 로그인 전후 메뉴와 모바일 메뉴
- 마이페이지의 로딩, 로그아웃, 빈 주문, 주문 목록 상태
- 저장 배송지 자동입력과 사용자 입력 보호
- 회원 주문 저장 성공 후 장바구니 삭제
- 주문 저장 실패 시 장바구니 유지
- 비회원 주문에서 Firestore 호출 없음

### Firestore 규칙 테스트

- 본인 회원정보 읽기·생성·허용된 필드 수정 허용
- 타인 회원정보 접근 거부
- 불변 회원 필드 변경 거부
- 본인 주문 생성·조회 허용
- 타인 주문 접근, 주문 수정·삭제, 잘못된 소유자·상태·금액 거부
- 기존 관리자와 상품 규칙 회귀 방지

### 완료 검증

- 전체 Vitest 테스트
- ESLint
- `next build` 기반 Vercel 빌드
- 기존 Vinext 빌드
- 운영 브라우저에서 가입, 로그아웃, 로그인, 비밀번호 재설정 요청, 배송지 저장, 회원 주문내역 확인
- 모바일 너비에서 계정 메뉴와 폼 확인
- Vercel 배포 상태와 런타임 오류 확인

## 배포 전제

Firebase Console에서 Email/Password 로그인 제공업체가 활성화되어 있어야 한다. Vercel의 기존 Firebase 공개 설정값 7개와 사이트 URL 값은 그대로 사용하며 새로운 클라이언트 비밀값은 추가하지 않는다. Firestore 규칙 변경은 앱 배포와 별도로 Firebase 프로젝트에 배포해야 실제 운영 데이터 접근이 가능하다.
