# VITALEAF 장바구니·비회원 주문조회·헤더·연령 추천 개선 설계

## 목표

장바구니에 상품이 제대로 담겼는지 즉시 확인하고, 수량과 결제 예정 금액을 한 화면에서 빠르게 수정할 수 있게 한다. 비회원 주문을 실제로 저장하고 안전하게 조회할 수 있는 흐름을 추가하며, 데스크톱과 모바일 헤더에서 자주 쓰는 장바구니·마이페이지·주문조회 접근성을 높인다. 연령별 추천은 관리자가 상품별 적합 연령을 명시한 경우에만 노출해 어린이·청소년에게 성인용 상품이 자동 추천되는 문제를 막는다.

기존 Firebase, Next.js, Vercel 구조를 유지한다. 데이터베이스 교체나 별도 관리 시스템 도입 없이 사용자가 체감하는 편의가 큰 부분에 집중한다.

## 범위

### 포함

- 데스크톱 상품 상세의 장바구니 담기 완료 토스트
- 장바구니 수량 직접 입력과 실시간 금액 갱신
- 데스크톱 헤더의 마이페이지·비회원 주문조회 재배치
- 관리자 링크의 푸터 하단 이동
- 검색 버튼의 가로 `검색` 표기 보장
- 모바일 헤더의 장바구니·마이페이지 아이콘
- 비회원 주문의 서버 저장과 주문번호·휴대전화 기반 조회
- 비회원 주문조회 시도 제한과 개인정보 최소 노출
- 기존 Firebase 이메일 회원가입의 동작·오류·이동 흐름 재검증
- 추천 연령 `어린이`, `청소년`, `20대`, `30대`, `40대`, `50대+`
- 관리자 상품 등록·수정의 추천 연령 다중 선택
- 기존 목업 상품의 추천 연령 데이터 보강
- 단위·통합·Firestore 규칙·반응형 브라우저 검증

### 제외

- 실제 PG 승인, 결제 취소, 환불
- 관리자 주문 처리·송장 등록 화면
- 비회원 주문의 이메일·문자 알림
- 소셜 로그인
- 쿠폰, 적립금, 찜, 정기배송
- 데이터베이스를 Supabase로 이전하는 작업

실제 PG가 없는 현재 단계에서 주문 처리 백오피스까지 만들면 운영 규칙과 실제 결제 상태가 일치하지 않아 유지관리 부담이 커진다. 이번에는 구매자 흐름과 안전한 조회까지 완성한다.

## 채택한 접근

### Firebase 유지 + Vercel 서버 API

회원 계정, 상품, 회원 주문은 기존 Firebase 구조를 유지한다. 비회원 주문은 브라우저에서 Firestore를 직접 읽게 하지 않고 Vercel의 서버 API가 Firebase Admin SDK로 생성·조회한다.

다른 접근은 다음 이유로 채택하지 않는다.

- 화면만 추가하는 방식은 조회할 실제 주문이 없어 사용자에게 거짓 기능이 된다.
- Firestore 클라이언트 직접 조회는 주문번호를 아는 사람에게 이름·전화·주소가 노출될 가능성이 있다.
- 별도 DB 도입은 현재 규모에서 설정·학습·동기화 비용 대비 체감 속도나 편의 차이가 작다.

서버 API 방식은 배포 비밀값이 추가되지만 개인정보 접근 경계를 명확히 하고 주문번호와 휴대전화의 복합 확인, 반복 조회 제한, 응답 마스킹을 한곳에서 관리할 수 있다.

## 사용자 경험

### 장바구니 담기 토스트

데스크톱 상품 상세에서 `장바구니 담기`를 누르면 화면을 가리지 않는 우측 하단 토스트를 표시한다.

- 상품명과 추가 수량을 보여준다.
- `장바구니 보기` 버튼과 닫기 버튼을 제공한다.
- 약 3초 뒤 자동으로 닫힌다.
- 같은 상품을 다시 담으면 수량과 타이머를 최신 값으로 갱신한다.
- `role="status"` 또는 `aria-live="polite"`로 화면 읽기 프로그램에도 결과를 알린다.
- 품절 또는 추가 실패 시 성공 토스트를 표시하지 않는다.

모바일은 공간을 많이 차지하는 팝업 대신 현재 버튼의 눌림 피드백과 장바구니 배지 증가를 우선한다. 필요하면 한 줄짜리 하단 알림만 사용하며 구매 버튼을 가리지 않는다.

### 장바구니 수량 직접 입력

현재 `− / 수량 출력 / +`를 `− / 숫자 입력 / +`로 바꾼다.

- 숫자 입력이 유효하면 `CartContext.setQuantity`를 즉시 호출한다.
- 기존 `summary` 계산을 재사용해 상품 합계, 배송비, 결제 예정 금액을 같은 렌더링에서 갱신한다.
- 허용 범위는 1부터 현재 재고까지다.
- 사용자가 편집 중 잠시 빈 값을 만들 수 있도록 입력 문자열은 컴포넌트 로컬 상태로 둔다.
- 빈 값, 문자, 0 이하는 `blur` 또는 Enter에서 마지막 유효 수량으로 복원한다.
- 재고 초과는 재고 수량으로 보정하고 이유를 인접 안내문 또는 접근 가능한 상태 메시지로 알린다.
- 모바일 숫자 키패드가 열리도록 `inputMode="numeric"`를 사용한다.
- 기존 `−`, `+` 버튼과 키보드 접근성을 유지한다.

수량 변경으로 합계가 바뀔 때 별도의 저장 버튼은 두지 않는다. 사용자가 수정 후 다시 저장하는 단계를 없애는 것이 가장 큰 편의 개선이다.

### 데스크톱 헤더와 푸터

공개 헤더에서 관리자 링크를 제거하고 마이페이지를 고정된 계정 진입점으로 제공한다.

- 로그아웃 상태: `로그인`, `회원가입`, `마이페이지`, `장바구니`, `주문조회`
- 로그인 상태: `마이페이지`, `로그아웃`, `장바구니`
- 로그아웃 상태에서 `마이페이지`를 누르면 `/login?next=/mypage`로 이동한다.
- 비회원용 `주문조회`는 장바구니 바로 오른쪽에 둔다.
- 로그인 회원은 마이페이지 주문내역이 있으므로 별도 주문조회 링크를 중복 표시하지 않는다.
- 관리자 링크는 푸터의 가장 아래 보조 링크 영역에 `관리자 로그인`으로 표시한다.

검색 버튼은 텍스트 자체를 유지하면서 최소 너비와 `white-space: nowrap`을 적용해 초록 버튼 안의 `검색`이 세로로 나뉘지 않게 한다.

### 모바일 헤더

모바일 우측 상단에는 텍스트를 숨기는 CSS에 의존하지 않고 명시적인 아이콘 버튼을 둔다.

- 장바구니 아이콘과 현재 상품 개수 배지
- 장바구니 오른쪽 마이페이지 아이콘
- 각 링크는 최소 44×44px 터치 영역
- 보이는 눌림·포커스 상태
- `장바구니, 상품 N개`, `마이페이지` 접근성 이름
- 로그아웃 상태의 마이페이지는 로그인 후 원래 목적지로 복귀

모바일 메뉴 안의 중복 관리자 링크는 제거하고 관리자 진입은 푸터로 통일한다.

### 회원가입

회원가입은 새로 이중 구현하지 않고 현재 Firebase Authentication 기반 화면을 검증·보완한다.

- 이름, 이메일, 비밀번호, 비밀번호 확인, 필수 약관 검증
- 중복 이메일, 약한 비밀번호, 네트워크 오류의 한국어 안내
- 중복 제출 방지와 처리 중 상태
- 계정과 회원 프로필 생성, 인증 메일 발송
- 성공 후 마이페이지 이동
- 헤더 로그인·회원가입·마이페이지 링크의 인증 상태별 표시

코드가 정상이어도 Firebase Console에서 이메일/비밀번호 공급자가 꺼져 있으면 가입할 수 없다. 배포 검증에 공급자 활성화와 Vercel 도메인 허용 여부를 포함한다.

## 비회원 주문 저장과 조회

### 주문 생성 흐름

비회원이 체크아웃을 제출하면 현재 목업 결제 검증 후 서버 주문 생성 API를 호출한다. 서버는 요청 값을 그대로 신뢰하지 않는다.

1. 요청 형식, 연락처, 주소, 상품 ID, 수량을 검증한다.
2. 서버에서 최신 상품 가격과 재고를 읽는다.
3. 합계와 배송비를 서버에서 다시 계산한다.
4. 고유 주문번호를 생성하고 주문을 저장한다.
5. 성공한 주문번호를 완료 화면에 반환한다.
6. 저장이 실패하면 장바구니를 비우지 않고 재시도 안내를 표시한다.

실제 PG 연동 시에는 같은 서버 경계 안에서 결제 승인 검증을 주문 저장보다 먼저 추가할 수 있다.

### 서버 경로

- `POST /api/guest-orders`: 비회원 주문 생성
- `POST /api/guest-orders/lookup`: 주문번호와 휴대전화로 주문 조회

조회는 URL 쿼리에 휴대전화 번호를 넣지 않는 POST 요청을 사용한다. 오류 응답은 주문번호가 틀렸는지 전화번호가 틀렸는지 구분하지 않는다.

### Firestore 데이터

`guestOrders/{orderNumber}` 문서는 다음 정보를 가진다.

- `orderNumber`
- `status`
- `paymentMethod`
- `customerName`
- `phoneNormalized`
- `postcode`, `address`, `addressDetail`
- `lines[]`: 상품 ID, 이름, 단가, 수량, 이미지
- `subtotal`, `shippingFee`, `total`
- `createdAt`, `receivedAt`

`guestOrderLookupAttempts/{fingerprint}`에는 짧은 시간 구간의 실패 횟수와 만료 시각만 저장한다. fingerprint는 원본 IP나 전화번호를 그대로 저장하지 않고 서버 비밀값을 포함한 해시로 만든다.

Firestore 클라이언트 규칙은 두 컬렉션의 읽기·쓰기를 모두 거부한다. 서버의 Firebase Admin SDK만 접근한다.

### 조회 보호와 응답

- 주문번호 형식과 정규화된 휴대전화가 모두 일치해야 한다.
- 일정 시간 안에 반복 실패하면 동일한 일반 안내와 함께 잠시 조회를 제한한다.
- 성공 시 주문일, 상태, 상품, 수량, 금액을 반환한다.
- 수취인 이름, 휴대전화, 주소는 마스킹해 반환한다.
- 서버 로그에 전체 전화번호, 주소, Firebase 비밀값을 남기지 않는다.
- 주문번호만 포함된 완료 페이지 URL만으로는 주문 개인정보를 조회할 수 없다.

### 주문조회 화면

`/order-lookup`은 주문번호와 주문 시 휴대전화 입력란, 조회 버튼, 결과 영역으로 구성한다.

- 주문 완료 화면에 `비회원 주문조회` 링크와 주문번호 보관 안내를 표시한다.
- 입력 오류와 조회 실패는 입력란 가까이에 표시한다.
- 결과에는 상태, 주문일, 상품 목록, 결제 예정 금액, 마스킹 배송정보를 보여준다.
- 로그인 회원에게는 마이페이지 주문내역을 우선 안내한다.

## 연령별 추천

### 데이터 모델

상품에 `ageTargets: AgeTarget[]` 필드를 추가한다.

허용 값은 다음과 같다.

- `child`: 어린이
- `teen`: 청소년
- `20`: 20대
- `30`: 30대
- `40`: 40대
- `50`: 50대+

관리자 상품 등록·수정 폼은 체크박스 형태의 다중 선택을 제공한다. 저장 시 허용된 값만 정규화하고 중복을 제거한다.

### 노출 원칙

- 연령별 메뉴는 `ageTargets`에 해당 값이 명시된 상품만 표시한다.
- 건강 고민 태그를 연령 추천으로 자동 변환하지 않는다.
- 특히 어린이·청소년은 관리자가 지정하지 않은 상품을 노출하지 않는다.
- 기존 Firestore 상품에 필드가 없으면 일반 상품 목록에는 유지하되 연령 추천에는 표시하지 않는다.
- 목업 상품에는 테스트 가능한 추천 연령을 명시한다.
- 결과가 없으면 오류 대신 `현재 등록된 추천 상품이 없습니다`와 전체상품 이동을 제공한다.

추천 연령은 의료적 적합성 판정이 아니라 쇼핑몰 분류임을 관리자 도움말에 명시한다. 실제 표시 문구와 주의사항은 제품 표시사항을 우선한다.

## 오류 처리

- 장바구니 수량 오류는 입력값 가까이에서 복원 이유를 알린다.
- 비회원 주문 저장 실패 시 주문 완료로 이동하거나 장바구니를 비우지 않는다.
- 주문조회 실패는 계정 존재 여부나 주문 존재 여부를 추측할 수 없는 동일 메시지를 사용한다.
- Firebase Admin 설정 누락은 서버에서 안전한 일반 오류를 반환하고 비밀값을 화면이나 로그에 노출하지 않는다.
- 회원가입 설정 오류는 사용자가 조치할 수 있는 안내와 운영자 점검 항목을 구분한다.
- Firestore의 기존 상품에 `ageTargets`가 없어도 일반 목록과 상세가 깨지지 않는다.

## 테스트와 검증

### 자동 테스트

- 상품 추가 성공 시 데스크톱 토스트 표시·자동 닫힘·장바구니 이동
- 수량 직접 입력, 빈 값 복원, 최소·재고 최대 보정
- 수량 변경 즉시 소계·배송비·총액 변경
- 데스크톱 인증 상태별 헤더 링크와 관리자 푸터 이동
- 검색 버튼 텍스트와 접근성 이름
- 모바일 장바구니·마이페이지 아이콘, 배지, 터치 목적지
- 비회원 주문 서버 가격 재계산과 저장 성공·실패
- 주문번호·전화 일치/불일치, 마스킹, 반복 조회 제한
- guest 컬렉션에 대한 Firestore 클라이언트 접근 거부
- 회원가입 성공·실패·중복 제출·안전한 이동
- 추천 연령 정규화, 관리자 저장, 각 연령 필터, 빈 상태

### 통합·브라우저 검증

- 데스크톱 상품 상세 → 장바구니 토스트 → 장바구니 → 수량 입력 → 합계 갱신
- 비회원 체크아웃 → 주문 완료 → 주문번호·휴대전화 조회
- 회원가입 → 마이페이지 → 로그아웃 → 재로그인
- 모바일 390px 헤더에서 장바구니·마이페이지 아이콘 노출과 터치
- 데스크톱 헤더·검색 버튼·푸터 관리자 링크
- 여섯 연령 메뉴와 목업 상품 상세 진입

검증은 lint, 전체 Vitest, Next 프로덕션 빌드와 실제 브라우저 런타임을 모두 포함한다.

## 배포와 설정

Vercel에는 기존 공개 Firebase 설정 외에 서버 전용 Firebase Admin 자격 증명과 조회 fingerprint용 비밀값이 필요하다. 예시는 다음 역할로 분리한다.

- Firebase Admin project ID
- Firebase Admin client email
- Firebase Admin private key
- guest lookup hashing secret

서버 전용 값에는 `NEXT_PUBLIC_` 접두사를 붙이지 않는다. 값은 저장소에 커밋하거나 채팅·로그에 출력하지 않는다. 배포 단계에서 Firestore 규칙을 게시하고 Firebase Authentication의 Email/Password 공급자 및 Vercel 프로덕션 도메인을 확인한다.

실제 운영 배포와 비밀값 등록은 코드 검증 후 사용자의 명시적 승인 범위에서 수행한다.

## 완료 기준

- 데스크톱에서 상품 추가 결과가 즉시 보인다.
- 장바구니 수량을 키보드로 입력하면 저장 버튼 없이 결제 예정 금액이 갱신된다.
- 데스크톱과 모바일에서 장바구니·마이페이지 목적지를 쉽게 찾을 수 있다.
- 관리자는 공개 헤더가 아니라 푸터에서 접근한다.
- 비회원 주문이 저장되고 주문번호·휴대전화가 모두 맞을 때만 마스킹된 주문 정보를 조회할 수 있다.
- 회원가입이 실제 Firebase 설정을 포함해 동작한다.
- 여섯 연령 메뉴가 관리자 지정 상품만 보여주며 어린이·청소년에 성인용 상품을 자동 추천하지 않는다.
- 변경된 모든 흐름이 자동 테스트, 프로덕션 빌드, 데스크톱·모바일 브라우저 검증을 통과한다.
